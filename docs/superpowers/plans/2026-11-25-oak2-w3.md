# Oak 2.0 — Wave W3 (Variation + habits) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The learner can grow an idea by varying it and can see their own habits: siblings (copies that each change one dimension the learner picks, played back to back and described), generations (a chain of children, each changing one dimension against its parent, with a note when a child changes back what its parent changed), transforms on the line under the cursor written as code (transpose, invert around the centre, retrograde, `.rev()`, rotate, time shift, snap to the key's scale, add a harmony), derive a part (one line's rhythm on another's notes, drums as a melody, a melody as drums), misuse moves (`.segment`, `.chop`/`.striate`, `.ply`); a deck of cards that describe and never tick (constraints, avoidance cards with "instead, try…", amateur cards, "one part only today"), a "With a card" start, a habits mirror read from the learner's own sketches with "Not this time", a catalog of attributes, an "outside your lane" prompt, "just play" on light days, and a tempo try.

**Architecture:** One short integrator stage (Task 6 stage 0) lands what several tasks share before anyone starts: Oak's defaults and the verdict-word check moved into `@oak/content-kit` (so the server's habits core and the grader's card checkers can use them), the card types, `readPiece` (the worker's analysis of a piece, now saved with every Studio version in the existing `sketch_versions.analysis_json`), two widened Studio seams (`EditorSlotProps.saveVersion`, `lastRunCode`, `meter`, `keySpec`; a `START_SLOTS` registry in the new-sketch dialog), an empty card-deck registry, and the contract additions (`CATALOG_REF_KINDS` gains `outside`, the habit id grammar, the lineage rules). Then two Opus agents work in the `oak2` worktree on disjoint files while three Codex Astra runs build the lineage service, the habits core and service, and the card deck with its checkers in their own worktrees. The integrator merges the Codex branches as soon as they are proven (stage A: services, route mounts, exports, the card deck registry) and wires the rest at the end (stage B: the catalogs service, the editor and start slots, contracts, the seam doc, the wave gate, the commit). New server services build what they read from `ctx.repos` and export a route function that takes the service, so no worker edits `Services`, `app.ts` or `OAK2_PENDING`.

**Tech Stack:** TypeScript, Bun, bun:test, React 19 + TanStack Router/Query, Strudel 1.2.6 (headless via `@oak/grader/testing` `evalHeadless(code, bars)` and the grader's `strudel(code, bars)` fixture in `packages/grader/src/analyze/__support__/fixtures.ts`), SQLite (STRICT tables), Hono, zod, Biome, Playwright (`*.pw.ts`, run only at the wave gate).

**Spec:** `docs/oak2/PLAN.md` (revision 2): §2 anti-goals and fidelity rules (binding), §4 S5 (Variation) and S6 (Cards and habits), §8 W3 row, §9 X15–X17, §10 calls, §11. ## Review Focus

The five ways W3 is likeliest to fail a real learner, each pinned by a test in its owning task:

1. **The habits mirror reads Oak's text as the learner's style.** A template's silent drum line (`s("bd*4 sd").n("~")`), Over a Band's `hats: s("hh*8")`, Oak's 90 BPM / 4/4 / C major, or a learning-kit copy shows up as "5 of your 8 sketches…". Pins: X16 AC 1–4 (the 9-sketch golden: sketch 8 is all silent template lines and counts for nothing; sketch 9's Band hats are ignored) and AC 9–10 (a learning-kit and a toolbox copy are not read) (Task 4); stage 0 `studio-defaults.test.ts` "OAK_START_NOTES match the notes Oak's starts write" (Task 6).
2. **A tool writes code that silently does nothing or drops notes.** Melody as drums through `.struct("0 2 4 7")` loses the degree-0 notes (0 is falsy in `struct`); a time shift written as `.early("1/8")` does not move anything (contracts §0.16: a fraction inside a string is "1 slowed 8 times"); a harmony or snap on a line it cannot change returns code that looks changed. Pins: `derive.test.ts` "melody as drums keeps every note, degree 0 included" and `rhythmMini` cases; `transforms.test.ts` "time shift writes a JS fraction and moves every onset by 1/8" and "a transform that cannot apply says why and leaves the code" (Task 1).
3. **The variation chain breaks or doubles.** Runs between generations make the next generation a child of the last Run (generation 1 again); a child names no parent or a wrong generation; "Keep" plus the next Run saves the same code twice. Pins: X15 AC 1–9 (validation, ordinary Runs never create generations, the chain first to last across Runs) (Task 3); `variation/model.test.ts` "keeping a generation after Runs names the chain's tip, not the last Run" (Task 1); stage 0 `piece-read.test.ts` and the `saveVersion` rule that it goes through the editor's own save queue (Task 6).
4. **Studio scores, or Oak reads first.** A card row says "missing" or ticks, an avoidance card blocks a Run, a habit sentence judges, a variation note says "should", or the catalog shows Oak's analysis of the reference before the learner has written. Pins: X17 AC 3, 5, 9 (every card and description passes `isDescriptive`; `describeCard` returns only a string) (Task 5); X16 AC 6 (Task 4); `cards/model.test.ts`, `catalog/model.test.ts` "Oak's reading is hidden until the sketch is written", `tempo-try.test.ts` "the BPM is named only after the pick" (Task 2); `variation/model.test.ts` "every note only describes" (Task 1).
5. **Saving a version gets slow or fails because the analysis rides with it.** A 128-bar analysis delays the save, an evaluation error throws inside the save queue, or the save waits on a hung worker. Pins: stage 0 `piece-read.test.ts` "analysisForSave gives null after the timeout and never throws" and "the analysis of an Aeolian loop names schema.aeolian" (Task 6); `w3-habits.pw.ts` "three Runs save three versions, each with an analysis" (Task 2).

Rules:
- **Transforms** (`TransformMenu`, slot place `toolbar`, acts on `cursorLabel`; disabled with "Put the cursor on a labelled line" when it is `null`):
  - transpose by `amount` (−12…12, the learner picks; none preselected): a line with `n(` and `.scale(` gets `wrapChain(code, label, "add", \`n(${amount})\`)` (inserted before `.scale`, a move in scale steps; the detail says "steps of the scale"); any other line `wrapChain(code, label, "transpose", String(amount))` ("half steps").
  - invert → `invertAroundCentre`; retrograde (pitches back to front, the rhythm kept) → `retrogradePitches`; mirror → `wrapChain(code, label, "rev", "")`; rotate by `amount` (1 by default, the learner can change it) → `rotatePitches`. The menu shows retrograde and mirror side by side, with one line each on the difference.
  - time shift (`amount` = 8 or 4, "an eighth of a bar" / "a quarter of a bar") → `wrapChain(code, label, "early", \`1/${amount}\`)` — a JS fraction, never a string (contracts §0.16).
  - snap to the key (`ctx.key ?? null`; `null` → `{ unchanged: "Set the sketch's key first; snap moves notes into its scale." }`) → `snapNotesToScale`; on an `n(…).scale(…)` line → `{ unchanged: "This line already plays scale steps, so every note is in the scale." }`.
  - add a harmony: an `n(…).scale(…)` line → `wrapChain(code, label, "superimpose", "x => x.scaleTranspose(2)")` (a third above in the scale; verified headlessly: C4 gets E4); any other line → `{ unchanged: "Add a harmony works on a line of scale steps: n(\"…\") with .scale()." }`.
  - misuse moves ("Misusing Rhythmic Tools", `misuse: true`, listed under their own heading "Use a tool the wrong way"): `segment` → `wrapChain(…, "segment", "16")`, `chop` → `"chop", "4"`, `striate` → `"striate", "4"`, `ply` → `"ply", "2"` (Oak's starting values, visible and editable in the code). Offered on every line; the detail says what each does to a busy line, a held pad, held chords, never when to use it.
  - Any transform whose result equals the input returns `{ unchanged: <why, in one sentence> }` and writes nothing. Otherwise `applyCode(result.code)` (one undoable change).
- **Derive a part** (in `TransformMenu`, heading "Make a new part from this one"): "Its rhythm on another line's notes" (pick the other line) → `deriveRhythm`: a new statement `<notesFrom>N: <notesFrom expr>.struct("<rhythmMini of rhythmFrom>")` inserted right after the `notesFrom` statement (its consts are already above it); "This drum line as a tune" → `drumsAsMelody`: `<freeLabel("mel")>: n("<drumsToDegrees>").scale("<Tonic>4:<mode>").s("<PLAIN_SOUNDS.tune>")` after the drum statement (key `OAK_DEFAULTS.key` when `null`); "This tune as drums" → `melodyAsDrums`: `<freeLabel("drums")>: s("<drum>").struct("<rhythmMini of mel>")` (the learner picks the drum; none preselected). The source lines stay as they are; the learner mutes what they like.
- **Siblings** (`VariationPanel`, slot place `aside`, tab "Siblings"): the parent is the version the editor shows when the learner starts (if the live code differs from it, "Save this as a version first" through `saveVersion`'s plain save is offered). "Add a sibling" asks for one dimension (sound, rhythm, notes, harmony, form; repeats allowed; no count suggested); "Change it" puts the parent's code in the editor (`applyCode`) and sets the draft `{ mode: "sibling", parentVersion, dimension }`; the learner edits and Runs as usual (ordinary versions); "Keep this sibling" calls `saveVersion({ ...keepFields(draft, sketch.versions), note: \`Sibling: ${dimension}\` })`. Each kept sibling row shows its picked dimension and, after `readPiece` of parent and sibling, `describeChange(dimension, diffDimensions(parentView, siblingView))`. "Play them back to back" = `BackToBack` over parent then siblings (bars = the sketch's loop length).
- **Generations** (tab "Generations"): "Next generation" asks for one dimension; the parent is `chainTip(sketch.versions, <the version the chain started from>)` (kept in the draft), so Runs in between never become parents; "Keep generation N" calls `saveVersion({ ...keepFields(draft, sketch.versions), note: \`Generation ${generation}: ${dimension}\` })`.
