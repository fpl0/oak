## Review Focus

1. A rule fed a piece with no events on its track (muted, misspelt label) must fail with a detail naming the missing track, never throw.
2. A piece with no `arrange()` (one loop) must be readable by every form rule: `ends-on-purpose` reads the last 4 bars, `staggered-boundary`/`carved`/`arc` fail with "needs sections" detail.
3. Band events (`band.*`) are never counted as the learner's parts by any rule.
4. Pieces in 3/4 and with a pickup: bar and beat arithmetic uses `ctx.meter`/`ctx.pickup`, not 4/4.
5. Migration on a real 1.4.0 database copy: runs once, is idempotent under the migrator, backup → restore round-trip keeps every row.

Each line has its test in the owning task (Tasks 2–4 step "edge pins", Task 1 step "migration round-trip").

### Task 2: Form and arrangement rules (Opus agent A2)

**Files:**
- Create: `packages/grader/src/rubric/oak2-form.ts`, `packages/grader/src/rubric/oak2-form.test.ts`

**Interfaces:**
- Consumes: `CorrectionDeps`, `CorrectionRule`, `CorrectionEval` (`corrections-rules.ts`); `sectionsFromAst` (`analyze/sections.ts`), `resolveSection`, `energyCurve` (`analyze/form.ts`), `formView` (`analyze/wave5-views.ts`), `selectTracks` (`analyze/tracks.ts`).
- Produces: `export function oak2FormRules(deps: CorrectionDeps): Record<string, CorrectionRule>` with keys `ends-on-purpose`, `carved`, `staggered-boundary`, `unique-event`, `arc`.

Rule specs (params, pass, fail):
- `ends-on-purpose` `{ modes?: ("exit-order"|"shrinking-tail"|"build-out"|"fades-out"|"cadence"|"final-hit")[] }` (default all). Reads the last section (`resolveSection("last")`) or the last 4 bars without `arrange()`. Passes when any mode holds: **exit-order** ≥ 2 parts stop inside the last section, in reverse order of their entry in the first section (ties allowed); **shrinking-tail** the last section repeats material from the bars before it and its repeat period shortens at least once; **build-out** parts are added across the last section and its final bar is its densest; **fades-out** summed event gain falls ≥ 9 dB across the last section while its material repeats ≥ 2 times; **cadence** the last chord change is V→I or IV→I in `ctx.key`; **final-hit** a final onset after which every part is silent ≥ 1 beat. Fails: the loop plays unchanged to the end. Detail names what was looked for ("the last section plays on like the others: let parts leave, shorten the loop, build, fade, or end on a chord").
- `carved` `{ minDiffer?: number }` (default 2). Every section's sounding tracks are a subset of the densest section's, each track plays the same per-bar material wherever it sounds, the densest section has every track, and ≥ `minDiffer` sections differ in which tracks sound. Fails: a section introduces material not in the densest section (an additive build passes `contrast` but fails here); all sections identical.
- `staggered-boundary` `{ min?: number; fill?: "anticipate"|"hesitate" }` (default 1). At ≥ `min` section boundaries, some but not all tracks change state ≥ 1 beat away from the bar line (extend into the next section, stop early, or leave a gap). With `fill`: a drum-density burst in the bar before the boundary that is silent on the downbeat (anticipate) or runs past it (hesitate). Fails: every track switches on the bar line; or every track is offset by the same amount (the boundary just moved).
- `unique-event` `{ min?: number; controls?: boolean }` (default 1). A track's bar material (onsets + pitches/drum roles; with `controls`, a control value) heard in exactly one bar, inside a section type that occurs ≥ 2 times. Fails: nothing happens once; the only once-heard material is a whole section (intro/bridge heard once).
- `arc` `{}` (optional suggestion). The densest section has a thinner section before and after it; adjacent repeats of the densest are allowed. Fails: densest first or last; flat density.

### Task 3: Pitch and harmony rules (Codex X2, worktree `Oak-wt/oak2-x2`)

**Files:** Create `packages/grader/src/rubric/oak2-pitch.ts`, `packages/grader/src/rubric/oak2-pitch.test.ts`.

**Interfaces:** Produces `export function oak2PitchRules(deps: CorrectionDeps): Record<string, CorrectionRule>` with keys `same-shape`, `bass-names-chord`, `inverted-copy`, `rotated-copy`, `time-shifted`, `gap-fill`.

Rule specs:
- `same-shape` `{ track?: string = "@chords"; minShifts?: number = 2 }`: every chord (≥ 3 simultaneous pitched notes on the track) has the same bottom-up semitone gaps; ≥ `minShifts` distinct transpositions; the track's code uses no `.voicing(`/`.voicings(`. Fails: `n("[0,2,4]").add(n("<0 3 4>")).scale("C:major")` (scale steps change the shape); one chord only; `.voicing()`.
- `bass-names-chord` `{ chords?: string = "@chords"; bass?: string = "@bass"; quality: string }`: the chord read from bass + chord tones (`@oak/theory` chord naming) has `quality` in ≥ 75 % of chord slots. Fails: the bass on a root that names another chord.
- `inverted-copy` `{ source: string; copy: string }`: same rhythm (onsets within 1/64 cycle); pitches mirror the source's around a fixed centre: scale degrees in `ctx.key` when set (sum constant), else midi (sum constant ± 1); ≥ 85 % of notes. Fails: a transposed copy; a reversed copy.
- `rotated-copy` `{ source: string; copy: string }`: same onsets; the copy's pitch order is the source's rotated by k ≠ 0. Fails: identical copy; shuffled copy.
- `time-shifted` `{ source: string; copy: string; min?: string = "1/16" }`: the copy equals the source shifted by one constant offset (mod the loop), offset ≥ `min` and ≠ 0. Fails: offset 0; two different offsets.
- `gap-fill` `{ track: string; ratio?: number = 0.6; leap?: number = 5 }`: of leaps (|interval| ≥ `leap` half steps), the share followed by motion in the opposite direction is ≥ `ratio`; leaps that belong to an arpeggio (consecutive same-direction leaps outlining one chord) are exempt; a melody with no leap fails ("no leap yet"). Fails: leaps always continued in the same direction.

AC (Codex): every rule has ≥ 2 passing and ≥ 2 failing pieces from the specs above plus Review Focus edge pins 1, 3, 4; every failing detail is one plain sentence; `bunx tsc --noEmit -p packages/grader/tsconfig.json`, `bunx biome check` on the two files and `bun test --isolate ./packages/grader/src/rubric/oak2-pitch.test.ts` pass; commit on branch `oak2-x2`.

### Task 4: Rhythm and sound rules (Codex X3, worktree `Oak-wt/oak2-x3`)

**Files:** Create `packages/grader/src/rubric/oak2-rhythm.ts`, `packages/grader/src/rubric/oak2-rhythm.test.ts`.

**Interfaces:** Produces `export function oak2RhythmRules(deps: CorrectionDeps): Record<string, CorrectionRule>` with keys `kick-bass-composite`, `hocket`, `stepped-control`, `no-chance`, `depth-layers`, `linear-drums`.

Rule specs:
- `kick-bass-composite` `{ bass?: string = "@bass"; window?: string = "1/32"; minBassPerBar?: number = 1 }`: no bass onset within `window` of a kick onset (`drum === "kick"`, learner tracks); no kick onset while a bass note sounds (`onset < kick < onset + (clipDur ?? dur)`); never two bass notes at once; ≥ `minBassPerBar`. Fails: a one-note token bass; a bass note ringing through a kick; bass on the kicks (Lock with the Kick).
- `hocket` `{ tracks: [string, string]; pitches: number[]; steps: 8 | 16 }`: the two tracks' events merged on the grid equal `pitches` (one midi per step, `-1` = rest) over each loop; never two notes at once (beat 1 counted); the tracks use different `s`; each track plays ≥ 25 % of the notes. Fails: one track plays everything; both on beat 1; same sound; call-and-response (whole phrases alternating) that breaks the line.
- `stepped-control` `{ track: string; control: string; minSteps?: number = 3 }`: per-onset control values form runs of ≥ 2 equal values separated by jumps of ≥ 20 % of the value range; ≥ `minSteps` distinct values. Fails: a sine read per note (every value different, small deltas); one constant value.
- `no-chance` `{ track?: string }`: the track's line (or the whole code) uses no chance tool (`?` in mini-notation, `degrade*`, `sometimes*`, `often`, `rarely`, `rand`, `irand`, `perlin`, `choose`, `shuffle`, `scramble`); detail lists what is still random.
- `depth-layers` `{ front: string; back: string[] }`: each back track repeats the same bar material in ≥ 75 % of bars; the front track has the most distinct bar patterns of all tracks; at least one back track has a bar (≤ 1 per 8 bars) where it is louder or busier than its own norm ("steps forward"). Fails: all tracks equally busy; no step forward; the front repeats like the back.
- `linear-drums` `{ group?: number[]; minHitsPerBar?: number = 6 }`: across the learner's drum events, no two onsets coincide (beat 1 counted); no drum role plays an even fixed grid across the bar (e.g. every 8th); with `group` (e.g. `[3,3,2]` in 8ths or 16ths scaled to the bar) role changes or accents fall on the group starts in ≥ 75 % of bars. Fails: a conventional beat with overlaps removed but hats still on every 8th; kick and hat together on 1.

AC (Codex): as Task 3, with branch `oak2-x3`.

### Task 5: Code rewrite module and dimension diff (Codex X1, worktree `Oak-wt/oak2-x1`)

**Files:** Create `packages/grader/src/rewrite/chain.ts`, `packages/grader/src/rewrite/degrees.ts`, `packages/grader/src/rewrite/rewrite.test.ts`, `packages/grader/src/analyze/diff-dimensions.ts`, `packages/grader/src/analyze/diff-dimensions.test.ts`.

**Interfaces — Produces:**
- `wrapChain(code: string, label: string, method: string, args: string): string` — appends `.<method>(<args>)` to the labelled line's chain (before a trailing `.scale(...)` when the method must act on degrees: `rev`, `early`, `late`, `scaleTranspose` go after `.scale`; `add` before).
- `rotatePitches(code: string, label: string, k: number): string` — rotates the numeric atoms of the first `n("…")` string by `k` positions, positions (rhythm) kept. (Strudel 1.2.6 has no `.rot`; decided during X1.)
- `rewriteDegrees(code: string, label: string, f: (d: number) => number): string` — rewrites the numeric atoms of the first `n("…")` argument of the labelled line via `readMini` offsets; non-numeric atoms untouched.
- `invertAroundCentre(code: string, label: string): string` — `rewriteDegrees` with `d ↦ min + max − d`.
- `retrogradePitches(code: string, label: string): string` — reverses the order of pitch atoms, keeping every atom's position (rhythm) — i.e. pitch values reversed across positions.
- `type Dimension = "sound" | "rhythm" | "notes" | "harmony" | "form"`; `interface PieceView { n: Normalized; code: string }`; `diffDimensions(a: PieceView, b: PieceView): Dimension[]` — sound: `s`/`bank`/control sets differ; rhythm: onset sets differ per track; notes: pitch sequences differ with onsets equal; harmony: chord slots (`pieceSlots`) differ; form: `sectionsFromAst` differ (a form change suppresses the rhythm/notes it implies).

AC (Codex): pure functions; a missing label returns the input unchanged; every output re-parses (`programInfo`) and evaluates (`strudel(code, 4)`); inversion keeps min and max on ≥ 10 cases; retrograde keeps onsets exactly; `diffDimensions` returns exactly one dimension on 10 single-change pairs (two per dimension) and exactly two on 4 double-change pairs; an added section returns `["form"]`; typecheck, biome, `bun test --isolate ./packages/grader/src/rewrite ./packages/grader/src/analyze/diff-dimensions.test.ts` pass; commit on branch `oak2-x1`.
