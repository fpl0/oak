# Oak 2.0 — Wave W1 (Studio core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The learner can start, grow and keep ideas in Studio without a lesson: scraps (an automatic index of every labelled line plus saved lines) and a capture-anywhere button (hum, tap, voice memo); starting points that are the learner's own (their Blank, setup-only templates, drums-and-bass first, plain start, fill it all, from scraps, from your head) with Oak's song templates relabelled as learning kits; jam then edit (takes, a timebox, a rough-pass row, keep/cut, build from takes); focus one part; plain sounds per role, listen-through, commit sounds; the tutor's honest stance and a Later list on Today.

**Architecture:** One short integrator stage (Task 9 stage 0) lands what several tasks share before anyone starts: a pure code-lines module in `@oak/content-kit`, the widened `TAKE_STATES`, and two empty registries (`app/src/studio/editor-slots.ts`, `app/src/capture/engines.ts`) whose types every task compiles against. Then four Opus agents work in the `oak2` worktree on disjoint files while four Codex Astra runs build self-contained pieces in their own worktrees (two server services, the tap quantiser, hum from a recording). The integrator merges the Codex branches as soon as they are proven (stage A: exports, route mounts, the capture engines registry) and wires everything at the end (stage B: Later routes, the editor slots, contracts, the seam doc, the wave gate, the commit). New server services build their repository from `ctx.repos.db` and export a route function that takes the service, so no worker edits `Repos`, `Services`, `app.ts` or `OAK2_PENDING`.

**Tech Stack:** TypeScript, Bun, bun:test, React 19 + TanStack Router/Query, Strudel 1.2.6 (headless via `@oak/grader/testing` `evalHeadless(code, bars)`), SQLite (STRICT tables), Hono, zod, Biome, Playwright (`*.pw.ts`, run only at the wave gate).

**Spec:** `docs/oak2/PLAN.md` (revision 2), §2 anti-goals and fidelity rules (binding), §4 S1–S4 and S7, §8 W1 row, §9 X5–X8, §11. Seam: `docs/design/oak2/W0.md` (tables, endpoints, `OAK2_PENDING` in `server/src/routes/oak2.ts`, rewrite API, known gaps).

## Review Focus

The five ways W1 is likeliest to fail a real learner, each pinned by a test in its owning task:

1. **Lines lost or broken when lines are combined.** Two scraps both labelled `bass`, or a `chords: chord(changes)` line whose `const changes` stays behind, give a sketch that drops a part or does not run (the existing `withDraft` replaces a line of the same label). Pins: `studio-code.test.ts` "scrapCode brings every const the line uses, transitively, in source order" (Task 9 stage 0); `scraps/model.test.ts` "two bass scraps become bass and bass2; both play" and "a chord(changes) scrap brings its const" (Task 1); `takes.test.ts` "build from takes keeps each picked line's consts and one line per label" (Task 3).
2. **Oak's defaults written into the learner's work.** The Blank's `bd hh sd hh` at 90 bpm, a start's sounds, or a "Make this my Blank" that keeps notes, later read by the habits mirror as the learner's style. Pins: `starts.test.ts` "the built-in Blank writes a tempo line and no part" and "no start writes pattern content outside OAK_DEFAULTS.lines" (Task 2); X7 AC 3–5 "a template from a sketch keeps tempo, meter and sounds, never notes" (Task 7).
3. **Jam leaks critique.** The tutor answers, a "Ahead of the course" callout appears, info squiggles show, the tutor's refusal talks about checkpoints, or the rough-pass row ticks or counts. Pins: `jam.test.ts` "jam chrome hides every hint, tip and compare and floors lint at error", "the jam subject is closed with the jam notice, not the checkpoint one", "the rough-pass row only describes" (Task 3); `w1-jam.pw.ts` (Task 3).
4. **Listening aids leak into the music.** A muffled listen-through recorded into an album take or meter reading, plain sounds written into the code or still on after leaving the sketch. Pins: `listen-through.test.ts` "the record tap and the analyser are fed before the listen-through stage" and `plain-sounds.test.ts` "only learner bass, chords and tune haps change; drums, Band and the code do not" and "off restores" (Task 4); `w1-sound.pw.ts` "leaving the sketch turns both off" (Task 4).
5. **Imported code runs unreviewed through a side door.** A backup's sketch line shown as an index scrap, a saved scrap or a template without `reviewBeforeRun`, then played or turned into a sketch without the strict lint. Pins: X6 AC 9 "index scraps of an imported version carry reviewBeforeRun" and AC 10 backup round-trip (Task 6); X7 AC 11 (Task 7); `scraps/model.test.ts` "a scrap to review makes a sketch to review" (Task 1); `starts.test.ts` "a template to review starts a sketch to review" (Task 2).
