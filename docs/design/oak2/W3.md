What W4–W5 can rely on after W3 (Variation and habits), and what W3 leaves open. The binding text is `docs/design/contracts.md` §13 (§13.3 W3 additions, §13.6 "W3 state"); this page is the seam between the waves. Plan: `docs/oak2/PLAN.md` revision 2 (§2 fidelity rules bind every wave: Studio describes, never scores; patterns, not rules), §4 S5 and S6; wave plan: `docs/superpowers/plans/2026-11-25-oak2-w3.md`. ## 5. Known gaps (W3 leaves these open)

1. **Habits read keys and schemas only from versions Run since W3.** Older versions carry `analysis: null`, so they give only text facts (and the version's own key).
2. **Over a Band in 3/4 reads as habits** (X16 supervisor finding, not fixed): `habitFacts` on an untouched `OVER_BAND_CODE_3_4` sketch at Oak's own 108 BPM gives `tempo 108` and `meter.3-4`, because tempo and meter are filtered against `OAK_DEFAULTS` (90, 4/4) only. The hats line is ignored. A possible fix: give tempo, meter, mode and key facts only to a sketch with at least one counted line (as `form` works); the golden output would not change. Needs the owner's call.
3. **Oak reads references only for unit songs.** A transcription, an audio file or an Outside-your-lane track gets the learner's lines only.
4. **The kit check is unverified headlessly**: the headless fixture never sets `bank` (W0 gap), so `cardFacts`'s kit and the `kit.*` card cases rest on hand-built events. The production `normalize` does set it.
5. **Siblings play without level matching** until W4 F5 feeds `BackToBack.gainOf`.
6. **Siblings and generations share one stored shape**; the Studio tells them apart by the `"Sibling: "` note. A chain started from a sibling continues its numbering. A sibling Run before Keep makes two versions (an ordinary Run version and the kept sibling).
7. **`saveVersion` has no plain save**: the variation panel's "save this as a version first" is a "Run it" button (the Run autosave makes the version).
8. **`$:` lines**: transforms act on the first statement with the cursor's label, so only the first `$:` line is reachable.
9. **Habit edge cases** (X16): a sound or kit named with a verdict word gives no sentence; when the first counted line has role `other` there is no `first` fact; two drum lines that differ only in punctuation share an id; a tempo of 90.4 counts (rounded after the default check).
10. **Browser-only parts unverified by unit tests**: `readPiece` in the browser worker (verified headlessly through the `strudel()` fixture only), BackToBack timing at item boundaries on real audio, the catalog flow's song player. The wave gate's browser specs (`w3-variation`, `w3-cards`, `w3-habits`, `w3-today`) cover the main flows.
11. **No `audio.list` endpoint**: catalog audio references are the distinct `audioId`s of the learner's transcriptions.
12. **Catalogs have no patch** (W0 gap 4): "Write from these lines" creates a sketch and a new catalog naming it; the lines-only twin is hidden in the list.
