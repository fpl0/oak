## 3. Grader rules (Tasks 2–4; registered by the integrator in `BUILT_CUSTOM_RULES` and `IMPLEMENTED.customRules`)

All custom rules return `CorrectionEval`; params are as the wave plan lists them.

- **Form and arrangement** (`packages/grader/src/rubric/oak2-form.ts`, `oak2FormRules`): `ends-on-purpose { modes? }` (exit-order, shrinking-tail, build-out, fades-out, cadence, final-hit; reads the last section or the last 4 bars), `carved { minDiffer? = 2 }`, `staggered-boundary { min? = 1; fill?: "anticipate" | "hesitate" }`, `unique-event { min? = 1; controls? }`, `arc {}`.
- **Pitch and harmony** (`oak2-pitch.ts`, `oak2PitchRules`): `same-shape { track? = "@chords"; minShifts? = 2 }`, `bass-names-chord { chords?; bass?; quality }`, `inverted-copy { source; copy }`, `rotated-copy { source; copy }`, `time-shifted { source; copy; min? = "1/16" }`, `gap-fill { track; ratio? = 0.6; leap? = 5 }`.
- **Rhythm and sound** (`oak2-rhythm.ts`, `oak2RhythmRules`): `kick-bass-composite { bass?; window? = "1/32"; minBassPerBar? = 1 }`, `hocket { tracks; pitches; steps }`, `stepped-control { track; control; minSteps? = 3 }`, `no-chance { track? }`, `depth-layers { front; back }`, `linear-drums { group?; minHitsPerBar? = 6 }`.

## 6. Known gaps after W0

1. **No handler is mounted** for the seventeen endpoints. `server/src/routes/routes.test.ts` "contract coverage" requires every contract endpoint to be served, so until each is mounted it must answer the typed 501 `not_implemented` like Waves 3–7 (a stub mount plus an `OAK2_PENDING` list in `routes.test.ts`); the builder removes a name there as its handler lands. The stub is outside Task 1's files: the W0 integrator adds it.
2. **Nothing writes the new columns yet.** `sketches.addVersion` accepts the 2.0 fields but the 1.4.0 library service ignores them; W1 (takes) and W3 (lineage) store them, and the repos read them back.
3. **No write path into `capstone_check_history`.** W4 records a row from the existing capstone check flow (the rubric check that sets `capstone_state.checked_sketch_*`) or adds an endpoint for it; contracts §13 needs a row when it does.
4. **`catalogs` has no patch.** `sketch_id` can be given at creation only; if W3's flow creates the catalog before the sketch, it adds `catalogs.patch` (contracts §13 first).
5. **Index scraps** (labelled lines of sketches) are computed per list, never stored; their ids are the scraps service's to define (stable per sketch version and label) and `scraps.delete` must refuse them.
6. **Habits** are `{ sketches, habits: { id, text }[] }`; X16's `summarizeHabits` must return that shape (or the integrator maps it).
7. **App** code reads none of the new fields yet; an app typecheck after W0 was not part of Task 1's proof.

## W0 close: what the integrator settled

- **Endpoints answer 501 until built.** `server/src/routes/oak2.ts` mounts every name in `OAK2_PENDING` (initially all of `OAK2_ENDPOINTS`) as the typed `not_implemented` stub. A W1/W3/W4 builder mounts the real handler in its own route module and removes the name from `OAK2_PENDING` in the same change; `routes.test.ts` "Oak 2.0 endpoints" then requires it to stop answering 501.
- **Rules registered.** `BUILT_CUSTOM_RULES` (`packages/grader/src/rubric/rules.ts`) spreads `oak2FormRules`, `oak2PitchRules`, `oak2RhythmRules`, each wrapped with `withAlsoUses`; the 17 names are in `IMPLEMENTED.customRules`. Content uses them as `{ rule: "custom", fn: "<name>", params }`.
- **Rule params as built** (beyond the wave plan's Task 2–4 specs):
  - every form rule takes an optional `tracks?: string[]` (default: every learner track); a named track with no events fails with a detail naming it.
  - `carved`: "only delete" includes erasing notes inside a part (a bar may be a sub-multiset of the same bar in the fullest section); `minDiffer` counts distinct line-ups.
  - `ends-on-purpose`: `cadence` and `final-hit` only count on a bar heard nowhere earlier (so a looping I–IV–V–I or a drum loop with a rest does not pass); `exit-order` counts a part as leaving only when its last bar and the silence after it are new.
  - `staggered-boundary`: shifts are read in the two bars around a seam and off the bar line only; a part moved by a whole bar does not count (a lesson wanting whole-bar staggers needs a `wholeBars` option).
  - `unique-event` and `staggered-boundary`, `carved`, `arc` need `arrange()` sections ("needs sections" detail); `ends-on-purpose` reads the last 4 bars without them.
  - `arc` treats a section as thinner at 25 % less density (Oak's call, from `CONTRAST_THRESHOLDS.densityRatio`; never shown to the learner).
  - `depth-layers` needs ≥ 8 bars to show its "steps forward at most one bar in 8".
- **Rewrite API** (exported from `@oak/grader`): `wrapChain`, `rewriteDegrees`, `invertAroundCentre`, `retrogradePitches`, `rotatePitches` (Strudel 1.2.6 has no `.rot`, so rotation is a visible rewrite of the line's numbers), and `diffDimensions(a: PieceView, b: PieceView): Dimension[]`.
- **Known gaps for later waves:** `bank` differences are detected in `diffDimensions` but the headless fixture does not set `bank`, so end-to-end bank detection is unverified; the form rules were tested through the headless fixture, not the browser realm's `normalize` (controls and role inference may differ slightly).
