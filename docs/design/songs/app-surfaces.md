# Oak app surfaces and look-and-feel: a map for the "each unit is one song" redesign

Scope: `app/src/` surfaces (Today, session machine and runner, lesson Make, Coda, Progress, Album, capstone, Studio,
the Oak map), the UI kit, styling, and routes. All paths are relative to `/Users/fpl0/Code/Oak`. Line numbers are
from the tree at `dec85d2`.

---

## 0. The short version

1. **A day is five routes in a row.** `/` (Today) → Start → `/session` (warm-up drills, then the lesson mounted
   in place, then its Make) → `/session/coda` → "Done for today" → back to `/`. A module-level runner
   (`app/src/session/live.ts`) drives the route changes and keeps the xstate machine (`app/src/session/machine.ts`)
   in step with a zustand store (`app/src/session/store.ts`). Today, the session and the Coda never talk about a
   *unit*. They talk about a *setlist* (Warm-up · New · Make · Coda) and a *lesson title*.
2. **Nothing persists from one Make to the next.** Each lesson's Make saves a new sketch
   (`app/src/lesson/server.ts:63-85`, `sketches.create`, `originKind: "lesson-make"`). The Band under it is a
   read-only loop with three fixed roles (`drums | bass | chords`, `packages/strudel/src/types.ts:79-86`). It is
   chosen per step (`BandRef.tracks`) in the profile's single flavour (`LessonPlayer` passes
   `profile.data?.flavour`, `app/src/lesson/LessonPlayer.tsx:256`). Only capstones keep one draft across sessions
   (`app/src/capstone/draft.ts`, `CapstoneResume`).
3. **Code already marks Oak's parts apart from the learner's:** every Band track is `band.<role>`. The grader's
   form view lists *learner* tracks per section (`packages/grader/src/analyze/wave5-views.ts:30-33,61-71`). The roll
   draws Band notes at 55 % opacity (`app/src/workbench/PianoRoll.tsx:651`). The transport shows Band parts as
   "drums (band)" chips (`app/src/workbench/TransportBar.tsx:286-319`). "Who owns a part" can be built on this
   convention. Two things the song model needs do not exist yet: sections in the Band, and a mute per section.
4. **The app feels bare because the daily surfaces show no music.** Today is a text setlist in a card and a column
   of small glance cards. It has no sound, no picture of what you are making, and no motion. The Coda is a 48rem
   column of bordered cards that fade in together. The "Sketch saved" card is a title and a link. Saturated colour
   is reserved for musical meaning (`app/src/ui/theme/tokens.css:1-4`), so a page without music has almost no
   colour. The richest visuals are SVG pieces that appear only off the daily path: tree-ring covers, the vinyl, the
   illustrated Oak, the unlock ceremony. There is no raster imagery at all; `app/public` holds only `boot.js` and
   `sw.js`.
5. **Many visual pieces exist and are unused.** In the kit, `SectionRibbon`, `MediaCard`, `AlbumPlayerBar`,
   `LineChart`, `KeyStrip`, `BranchCard`, `VersionSwitch`, `VersionList`, `EuclidRing`, `DeviceCounter` and
   `LoudnessReadout` appear only in the `/dev/kit` gallery. Ready parts for a song view: `FormStrip` (capstone), the
   onboarding `LayerRow` ("the four musicians", one per part), `PatternPlayer` (`setLoop`, `setMutes`,
   `position()`), tree-ring covers, and `SketchCover` (one ring per saved version: "the song grows a ring each
   lesson").

## 2. What the learner sees each day, screen by screen

### 2.0 The machinery (data flow)

```
TodayPage ──onStart(plan)──▶ sessionRunner.start(plan)            app/src/session/runner.ts:268-297
                               ├─ POST session.start  + baseline (skills.map, cando.list)
                               ├─ useSession.begin(plan, session)  (store.ts; block = firstBlock(plan))
                               └─ launch(): xstate actor(sessionMachine) + 1 s tick (ActivityClock, heartbeat, persist)
store.block changes ──SYNC──▶ machine (forward only: warmup→main→make→coda)   machine.ts:96-204
machine entry onBlock ──▶ runner navigates: "/session" for every block, "/session/coda" for the Coda
                          (stays on /learn|/checkpoint when the lesson played there reaches its Make) runner.ts:207-218
coda.entry ──invoke endSession──▶ POST session.end → SessionSummary → view.summary (CodaPage reads it)
"Done for today" ──▶ sessionRunner.finish("/")  → store.reset, navigate "/"
```

- `SessionPlan` (`packages/api/src/dto.ts:1374ff`) has `kind`, `mapItemId`, `title`, `note`, `warmup` (DueBatch),
  `main {resumeStep, splitPart, light, estMinutes}`, `returning`, `alternatives`, `tutorNote` (no longer shown),
  `sideLesson`, `slot`, `tracks`, `core`, `track`, `trackOffers`, `focus`, `course`. **The plan has no unit or song
  field.**
- `SessionState` (`app/src/session/types.ts:51-70`) holds `plan, session, block, warmupIndex, reports[], activeMs,
  phaseMs, wrap, wrappedEarly, paused`. `BlockReport` (:25-47): `{block:"make", source:"lesson"|…, sketchId}` is the
  only record of what the Make produced.
- Blocks per kind: `blockBudget` / `nextBlock` (`store.ts:46-108`). Capstone and gym days have no separate Make
  ("the draft is the Make").
- Persistence on reload: `session/persist.ts` (`saveActive`, `saveEnded`, `EndedRecord`).
- React bindings: `session/hooks.ts` (`useRunnerNavigator`, `useRunnerView`, `useLastEnded`).
- Day overlays are a recurring pattern: a pure model plus a hook joined by `day-hooks.ts`
  (`useCapstoneDay`, `useGymDay`, `useCftDay`, `useAfterCore`, …). Each feeds `todayView()` and the Coda. **A
  `useSongDay(plan)` and a pure `song-day.ts` would follow this exact pattern.**

  - Live grading on a 700ms debounce plus every Run (`h.gradeQuiet`); the check is never posted.

## 3. Why the app can feel "bare": what the code and CSS show

**The daily path is text and controls.**
- Today's main card is an ordered list of four or five text rows (`Setlist`, `TodayPage.tsx:76-99`). Each row is a
  number in muted Fraunces, a label, minutes, a detail line, and an optional objective line. The row says "Make · 4
  min · A short sketch with today's tools", but you cannot hear anything from Today. There is no ▶ anywhere on the
  page.
- Count of prose lines Today can stack under the setlist: the lead, `TrackSessionLine`, `GymExplain` /
  `CftStrip` explain lists, `OtherTabLine`, the Keep-alive link, `SideOfferLine`, `TrackOffers`, four `Callout`s
  (rest day, repair, loosen, X1), `OpenToYou`, `TracksLine`, "Other ways today", and the aside footer sentence.
  Much of this is honest-copy policy ("one line, never a count") and is heavily e2e-tested by `data-testid`.
- The aside's four cards use a small `text-sm font-semibold text-text-2` header (`CardTitle`, `Glance.tsx:25-32`)
  over a line of text or a link. Only the mini Oak is a picture. Early in the course the album strip is three
  dashed circles.
- The Coda's "Sketch saved" card is a title and a link. "On the Oak" is a text list. "Next" is text. The one
  animated moment is the unlock ceremony, and it happens only on unlock days.
- The lesson prompt column is reading-first: an uppercase micro label, a title, MDX prose, the "Your task" box.
  The Band, the thing that "makes a Make sound like a song", shows up only as transport chips "drums (band)" and
  55 %-opacity notes. **The learner never sees a song, only a 1–4-bar loop.**

**Colour is reserved by rule.**
- Chrome is warm neutral: Paper bg `#f6f2ea`, surface `#fffdf8`, surface-2 `#efe9de`, border `#ddd3c3`. Accent oak
  green `#2f6b45` and acorn amber `#b7791f` are used for buttons, chips, active states and thin left borders. The
  only fill tint is `--oak-lane-in` at 6 % green. The tokens file says it outright: "saturated colour is reserved
  for musical meaning (palette.ts)".
- The saturated palettes (Okabe–Ito degree colours, `PARTS_PALETTE`, the wood colours of the covers) appear only
  where music is drawn: the roll, staff, covers, tree and keyboard. Today and the Coda draw almost no music, so
  they stay beige.
- Shadows are faint in Paper (`0 1px 2px …/.06, 0 4px 12px …/.05`) and **absent in Bark** ("Bark uses borders,
  not shadows"). Every card is the same `rounded-card border border-border bg-surface`, and no surface is raised
  above the rest.

**Little motion.**
- `app.css:62-101` defines only `fade-in`, `slide-in-right`, `pop-in` (200ms) and the skeleton `shimmer`.
  `animate-fade-in` appears in about 12 places, mostly Coda cards and overlays (Dialog, Toast, Tooltip, palette).
  Today has no motion apart from loading skeletons.
- Richer motion exists but sits off the daily path: the cover draw-in (`album/cover.css`: rings 480ms, staggered
  110ms each), the vinyl spin (7.2 s), the unlock showcase (`CodaUnlock`), the build-up in onboarding's
  `LayerRow` (`transition-colors duration-200`), and the StepRail's width transition.
- Under reduced motion everything collapses to ≤120ms (`app.css:222-235`, `tokens.css:178-183`). `motion.ts` has
  `onNextDownbeat()` for beat-synced ceremony; it is barely used.

**Layout is sparse.**
- Page widths: `--oak-page-wide: 72rem` (most pages), `focus: 60rem`, `narrow: 48rem` (Coda), and `measure: 62ch`.
  Cards use `p-4`/`p-5` with `gap-4`/`gap-6`. Today's main column is about 700px of content on a 1440 screen,
  holding a short list.
- The page headers (`PageHeader`, `basics.tsx`) are an h1 and a sub line. There are no hero areas, no covers in
  headers (except the Album sleeve), and no illustration slots.

**The spec promised more than was built.** Compare ux.md §1.4–§1.5 with the code. Missing on Today: the Next
unlock progress bar and ▶, the ▶ on Last sketch, and Claude's note (removed). Missing in the Coda: the mini-roll
thumbnail, ▶ and rename on Sketch saved, the 320px tree, the staggered card animation, and the teaser ▶. UI sounds
exist (`packages/strudel/src/ui-sounds.ts`; ux.md §7.7: "session complete V → I").

**Where Oak does look rich:** `/album` (sleeve, vinyl, 300px covers, the record sides), `/oak` (the illustrated tree
with acorns for released tracks), the capstone workspace (form strip, track cards, part levels, ceremony dialog with
a cover drawing itself), and the onboarding loop (four musicians entering bar by bar). **Each is a destination the
learner rarely visits during a normal lesson day.**

## 5. Where a song view would live

A song view has sections as columns, parts as rows, each cell marked as the learner's or Oak's, a ▶ button, and a
line saying what today adds. Its data shape probably looks like:
`{ unitId, title, flavour, sections: {tag, text, letter, startBar, bars}[], parts: {id, label, owner: "oak"|"you"|
"today", cells: {sectionTag, owner, lessonId?}[]}[], code, band, todayAdds: {partId, sectionTags[], line} }`.
Every surface below can render it once a pure model exists, for example `app/src/session/song-model.ts` with a
`useSongDay(plan)` in `day-hooks.ts`.

### 5.1 On Today (`TodayPage.tsx`)

- **Primary placement:** a new song card at the top of the main column, above or merged with the setlist card
  (:485-579). The day's one decision ("Start session") would then sit under the song. Use a pure `todayView()`
  field `song` (`today-model.ts:66-95`) so all 15 states stay unit-tested.
  - `normal`, `resume`, `split-*`: show the song with today's cell highlighted ("Today you take over the bass in the
    chorus"). The setlist "Make" row detail (`setlistRows`, :244-250) becomes that line.
  - `in-session`: the song plus "Resume session".
  - `done`: the song with today's cell now "yours", plus ▶ "Hear it now". `DoneCard` (:194-264) currently has only
    text.
  - `checkpoint`: the song with no new cell (or the unit's last cell).
  - `capstone` and the unit-end release: the song as "ready to release", using the `CftStrip` stage-tile pattern
    (`TodayWave6.tsx:12-67`).
  - `first-run`, `paused-week`, `review`, `gym`, `edge`: probably a smaller form, or none at all.
  - `welcome-back` / `light`: the light session revisits an earlier Make. Decide whether it edits the song.
  - The flavour pick happens when a unit starts. The precedents are the onboarding flavour preview with audible ▶
    (`onboarding/screens/PrefsScreen.tsx:17-24,59-80`, a `PatternPlayer` loading `previewCode(f)`) and the capstone
    flavour `SegmentedControl` (`capstone/CapstoneScreen.tsx:240-243,460-469`).
- **Aside:** `AlbumStrip` (`Glance.tsx:118-189`) could show this unit's song cover growing, using `SketchCover` (one
  ring per version) or a seed-only `AlbumCover`. `LastSketchCard` becomes redundant if the song is the sketch.
- **Header:** the song title and cover could become the hero beside the weekday (`Header`, :119-151).
- **Playback:** `PatternPlayer` (`packages/strudel/src/types.ts:275-317`) can do everything the card needs.
  `load(code, {bars, cps, band, key})` plays song and Band together. `setLoop({fromBar, bars})` plays a clicked
  section column. `setMutes(MuteMap)` solos or mutes a clicked part row. `position()` drives a playhead over the
  grid. Working examples of headless play-from-the-top: `session/host/CapstoneResume.tsx` (:77) and
  `session/host/RecapCard.tsx` (:58).

### 5.2 In the lesson

- **During teaching steps** (`StepLayout`, `lesson/frame.tsx:143-235`): a thin "song strip" under the step's
  kind label in the prompt column (:183-196), or a strip above the stage. It would show where today's idea will go.
  The FocusBar could carry the song name next to the lesson title (`AppShell.tsx:186-189`, via
  `useFocusHeaderContent`).
- **The Make** (`MakeRenderer`, `lesson/renderers.tsx:568-748`) is where the take-over happens:
  - answer column (`answerFirst`): replace the `make-start` `Callout` (d15 "Your own sketch / Oak's copy") with
    "Your song so far". `make-start.ts` is the exact precedent: `fromSketch` opens with the learner's earlier
    sketch, and "Start from Oak's copy" brings back the starter. Add the song grid with today's cell, then the
    rubric checklist ("the one that counts today").
  - stage: the `Workbench` takes a `toolbar` slot (`Workbench.tsx:191,1587`) that can carry a compact song bar: a
    section ribbon plus part rows with mute and solo. The Workbench already has `initialMutes` and `onMutes`, and a
    section ribbon over the roll (`workbench/SectionRibbon.tsx`) that appears when the code uses `arrange()`.
  - band: today `bandSetupOf(step.ui.band, {flavour, key, bpm, at})` (`lesson/band.ts:14-36`). "Oak plays every
    part except the one you took" maps onto `BandRef.tracks` and the mutes. **Taking over part of a part (one
    section) is not representable** (see §7).
  - save: `createSketch` (`lesson/server.ts:63-85`) would become "add a version to the unit's song sketch", like the
    capstone's `useDraftSaver` (`capstone/draft.ts`). The `{block:"make", sketchId}` report stays the same.
- **`CompleteScreen`** (`lesson/screens.tsx:17-173`): add the song with the new cell lit, plus [▶ Hear your song].
  Done for a take lesson finished outside a session: the Coda's `SongGrew` card ("Before today", "With today", "Open
  the song", "Open today's code in Studio") above the back button; inside a session the Coda shows it.

### 5.3 In the Coda (`session/coda/CodaPage.tsx`)

- Replace `SketchCard` (:115-135, rendered at :355) with a "Your song grew" card: the grid with today's cell
  marked, ▶ from the top or from today's section, and the cover growing a ring. `ReleaseCard`
  (`CodaWave4.tsx:44-195`) already does the matching job for a release (cover 136px + "joins your album") and can
  take the unit-end release as is.
- The header's "Today you: …" (`todayLines`, `coda-model.ts:103ff`) could say "took over the bass in the chorus".
- "Next" (:486-533) could say what tomorrow adds to the song: "Next time: the chorus gets your melody". This could
  be the ▶ teaser from ux.md §1.5, which was never built.
- `ListeningNote` (:137-178) already reads `summary.sketchesSaved[0]`. Pointed at the song, Claude would listen to
  the whole song.
- Add the song query key to `SESSION_ENDED_KEYS` (:75-102).

### 5.4 As its own route

- Option A: **`/song/$unitId`** (or `/songs/$songId`), a shell route with a `routes/song/$unitId.tsx` file. It would
  hold a large song view, the cover, the lesson by which each cell became yours (a timeline of versions), and
  playback. Add it to `NAV_ITEMS` if it becomes a destination, and to `isSessionSurface` (`runner.ts:83-90`) if it
  can be opened mid-session.
- Option B: fold songs into the **Album**. `/album/$trackId` (`album/TrackPage.tsx`) already has a 360px cover,
  liner notes, recording, live code, a version timeline with A/B, and revision. A unit song is a track whose
  versions are its lessons. `AlbumTrack.side` already allows `"Bside"` with `capstoneId: null, sketchId`
  (`packages/api/src/dto.ts:1702-1713`), a working precedent for a non-capstone track. Side A, though, is hard-wired
  to 12 capstones (`ALBUM_SIDES`, `dto.ts:3280-3287`; `album/model.ts:24-37`), while the core has 18 units
  (`content/core/U00…U17`).
- Option C: the Studio sketch page (`/studio/$sketchId`, `SketchEditor`) already edits a sketch with a Band, key,
  meter, length and version history. A song could open there for free play between lessons.
- Linked surfaces: the Oak tree (`map/illustrated/TreeDrawing.tsx:238-260`) draws released tracks as acorns placed
  by `capstoneId` and B-sides as fallen acorns. A unit's song could be an acorn on its unit's branch.
  `/progress` `CourseCard` (`ProgressPage.tsx:115-180`) lists units with a `Progress` bar, and each row could carry
  its song cover. The Oak's Course view (`routes/oak.tsx:37-174`) draws each unit as a card of lesson dots, where
  the song is a natural header.

## 7. Facts that make the song rework easy or hard

**Easy, or already there**
- `band.<role>` against learner labels is a consistent ownership line in the engine, grader, roll and transport
  (`wave5-views.ts:30-33`, `workbench/model.ts:490-522` `heardBand`, `PianoRoll.tsx:651`). Muting an Oak part (a
  step's `BandRef.tracks`, saved as `band.mutes`) is the existing way to "leave a part to the learner".
- Sections come from `arrange()` through the grader (`formView`, `sectionsFromAst`, `lib/form-view.ts`
  `formSectionsOf`), and each `FormSectionView` already lists the **learner tracks that sound in it**. That is the
  section × part matrix for the learner's half.
- A long-lived piece across sessions has a full precedent in capstones: the draft sketch (`capstone/draft.ts`), the
  session-bound saves, "play from the top" on resume, the Band on/off toggle (`Workspace.tsx:878-892`), the form
  strip, release with ceremony and cover. Capstone drafts handle up to 128 bars (`MAX_CAPSTONE_BARS`).
- `fromSketch` (d15, `lesson/make-start.ts`, `renderers.tsx:574-606`) already opens a Make with an earlier sketch,
  plus a "Start from Oak's copy" switch.
- `PatternPlayer` has `setLoop`, `setMutes` and `position()`; covers grow from any sketch version
  (`useCoverMusic`); `SketchCover` rings count versions.
- Pure models sit next to thin pages everywhere (`today-model.ts`, `coda-model.ts`, `capstone-day.ts`, …), each
  unit-tested, so a `song-model.ts` fits the house style.

**Hard, or needs new contracts**
- **The Band is three loop roles, not a song.** `BandSetup.tracks: ("drums"|"bass"|"chords")[]`
  (`packages/strudel/src/types.ts:79-86`). The sketch DTO's `bandState.mutes` is a strict enum of the same three
  (`packages/api/src/dto.ts:1584-1588`). There is no melody, pad or lead role, no sections (intro, verse, chorus),
  and no mute per section. "Replace part of one of Oak's parts" cannot be expressed today. The onboarding loop has a
  `mel` layer, but it is learner-side code, not Band.
- **Every Make makes a new sketch** (`lesson/server.ts:63-85`). The sketchbook, the Coda's `sketchesSaved[0]`,
  Today's `LastSketchCard`, the listening note and `fromSketch` all assume one sketch per lesson.
- **Flavour is a global profile setting** (`LessonPlayer.tsx:256`; Settings › Learning "Style", formerly "Genre flavour"). A choice
  per unit song needs its own store; the capstone keeps flavour per draft via sketch tags (`Workspace.tsx` `onFlavour`
  patches `tags`). Onboarding offers only pop and jazz-soul; indie and funk exist in `FLAVOUR_LABEL` and the cover
  woods.
- **Lessons are built around 1–4-bar loops** (`loopBars` default in `workbenchBase`). The Workbench roll pages every
  16 bars (`FOLLOW_PAGE_BARS`, `roll-layout.ts:319`) and analysis caps at 64 bars (`MAX_PIECE_BARS`,
  `lines.ts:116`). A whole song in every step's editor would change what each step shows. Lessons may need "today's
  loop" with the song around it, not the whole song.
- **The album is keyed to capstones** (`ALBUM_SIDES` holds 12 Side A capstones; the tree's acorns are placed by
  `capstoneId`; `album/model.ts` `SIDE_A_ORDER`). The core has 18 units (U00–U17). Either units map to album slots
  (some units share, some songs become B-sides), or the album model changes.
- **Session reporting has no song concept.** `BlockReport`, `SessionSummary`, `SessionPlan`, `EndedRecord` and
  `todayView` would each gain a field, and the server would have to plan "which part today adds".
- **The copy is heavily tested.** Today and the Coda have dozens of `data-testid`s and e2e specs
  (`app/src/session/**/e2e`, `app/src/lesson/e2e/*`). A Today redesign touches many specs.
